# 人生罗盘运行层

只在两层地图已经得到用户确认、用户又明确希望持续回看时使用。当前产品是 clone-first：`private/life-grid-monthly.json` 是唯一正式地图；coding agent 经确认后写入，Personal 网站只读呈现。这里不是后台监督、自动提醒或跨项目同步协议。

## 从方向到行动

64 个第二层位置是长期坐标，不是 64 项待办。每月从整张地图中选 1–3 个真正想推进的方向；未选中的方向仍然有效，不标为落后。

对每个当前重点，最多记录：

- 本月要验证的具体问题；
- 可重复的输入或实践；
- 一件有完成标准的行动或小实验；
- 用户真实提供的输出与证据；
- 期末回看时要问的问题。

计划与发生过的事要分开。Agent 可以建议行动或总结用户给出的事实，但不能替用户标记完成、编造结果，或把“前进证据的描述”当成已经发生的记录。方向变化也不从单次行动自动推断；必须另行展示候选并征求明确确认。

## 日常输入如何回流

用户可以用一句话、一个片段或一件真实产物更新。Agent 先判断它属于哪个已确认房间和方向；归属不清时询问，不强行塞进某一格。保存前展示最小摘要、来源、拟关联方向，以及它是计划、观察、已发生的事实还是仍待核实的说法。只在用户确认后按[输出与写入契约](output-contract.md)更新私人文件并回读。

原项目的代码、任务和日志仍留在原处；人生地图只保留用户同意的最小摘要或引用。不得主动扫描其他 Codex 会话、仓库、OpenClaw 或 Wiki 来“监督人生”。健康、关系、财务与家庭内容尤其要避免复制全文。

## 当前能力边界

公开 Example 只用于虚构教学与页面内试填，刷新后还原；公开 Blank 的显式导入只在当前浏览器暂存。二者都不是私人地图的权威源。当前版本没有八个领域 Agent、跨会话持续监控、定时追问、云端账本或网站自动写回；这些需单独设计、授权、实现与验证后才能宣称可用。
