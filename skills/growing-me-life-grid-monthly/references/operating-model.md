# 人生罗盘运行协议

当两层地图已经形成、用户希望持续运行时，使用本协议。它补充访谈流程，不替代人生地图 JSON。

## 当前三种角色

1. **单一人生罗盘会话**承接首次访谈、日常一句话、跨板块去重、月度 1–3 个重点和阶段答卷。它提出候选，不是人生地图的权威源。
2. **网站人生账本**保存用户已经接受的方向、回执、答卷与历史版本。AI 只能暂存候选；确认、退回和改变方向由用户完成。
3. **其他会话或项目**只是按需输入源。只有用户明确指定标题、读取范围和本次目的后，人生罗盘会话才可只读；它不能扫描全部历史、写入其他会话或接管项目。

不要把 64 个长期方向变成 64 项打卡。方向回答“长期想靠近什么”，项目与月度行动回答“现在怎样产生证据”。

当前阶段不创建八个领域会话。只有某个板块长期高频、单一会话上下文明显过长，且网站已经具备统一去重、版本冲突与确认门时，才考虑把它拆成专业审查镜头。

## 权威边界

| 内容 | 权威源 |
| --- | --- |
| 愿景、八个板块、长期方向 | 用户确认过的人生地图 |
| 项目当前状态与真实产物 | 原项目、仓库或对应任务 |
| 某项证据对人生方向的意义 | 人生罗盘会话的候选判断，经用户确认后进入账本 |
| 可选的外部知识或项目事实 | 原会话、原项目及真实来源；网站只保存最小摘要和引用 |
| 定时提醒状态 | 仅在用户另行配置后，以真实自动化运行回执为准 |

任何一层都不能把另一层的计划、摘要或旧记录冒充当前事实。

## 可选：项目怎样挂到板块

项目连接不是第一版长期回流的前置条件。先验证“用户自然输入 → AI 候选 → 网站确认 → 房间回看”的闭环；用户希望把真实项目接回来时，再使用以下规则：

- 每个项目只有一个主要板块，必要时关联 0–2 个次要板块。
- 项目任务清单、代码和日志留在项目内；人生账本只保存项目引用、它服务哪个方向、已产生的证据和仍有的差距。
- 同一证据只创建一次。多个板块需要它时引用同一个 `receipt_id`，不能重复计算。
- 只有已有项目无法覆盖已确认的关键差距时，才建议新建项目。
- 人生罗盘会话可以提出项目归属候选，不能擅自重命名、迁移或创建 Codex 项目。

## 领域回执

用户提供真实片段，或授权读取的会话/项目出现真实变化后，人生罗盘会话按 [DOMAIN_RECEIPT_v1 Schema](domain-receipt.schema.json) 生成回执。最少回答：

- 发生了什么；
- 来源在哪里；
- 属于哪个板块，是否明确属于某个长期方向；
- 证据是用户陈述、已有产物、已核验还是待核验；
- 它让目标更近、无变化、更远，还是暂时无法判断；
- 还差什么；
- 下一步是否值得成为候选行动。

`source_ref` 必须是真实任务、turn、文件、commit、文档或用户消息引用。只读到旧摘要不能标成 `verified`。重复提交同一 `receipt_id` 与同一内容应保持幂等；同一 id 的不同内容必须报冲突。

健康、关系、财务和家庭内容默认最小化。密码、API Token、账号、医疗报告全文、完整聊天和附件正文不得写入回执。需要保留但不应被站点工具读出的摘要标为 `sensitive`。

## AI 答卷

答卷必须引用已经存在的 `evidence_ids`，并分开写：

1. `summary`：本阶段最重要的判断；
2. `observed_change`：证据显示发生了什么变化；
3. `gap`：离已确认方向还差什么；
4. `next_focus`：最多一个值得用户确认的下一焦点。

单板块答卷不能引用其他板块的证据。跨板块月度答卷由人生总控生成。AI 答卷始终先是 `candidate`；用户确认答卷也不会自动改写长期方向，方向变化必须另行讨论和确认。

## 网站工具模式

当人生地图页面在支持站点工具的应用内打开时，人生罗盘会话可使用：

- `read_life_compass`：读取愿景、板块、方向与非敏感账本摘要；
- `stage_life_evidence`：把一批真实回执暂存为候选；
- `stage_life_review`：基于已有证据暂存候选答卷。

页面关闭、站点工具不可用或用户没有授权时，退回严格 JSON 导入。不得声称后台仍在监控。站点工具不提供确认动作；用户必须在页面中接受或退回。

## Wiki / OpenClaw 投影

本节是未来可选扩展，当前版本不启用，也不属于首次地图完成条件。

Wiki 不建立八份重复正文。继续使用一份不可变、有来源的共享记录；另建一张按八板块查看的链接索引即可。同一条记录可有一个主要板块和少量次要板块，索引只指向原记录，不复制正文。

任何 Wiki 写入继续遵守 `validate → sync → 回读 → receipt=synced`。OpenClaw 是入口、提醒和路由，不是人生账本的第四个权威源。是否创建索引页、回标历史记录或加入定时同步，必须由用户另行授权。
