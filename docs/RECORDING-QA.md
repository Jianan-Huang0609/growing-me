## 一句话判断

Example 展示“这样一张地图可以怎样组织、试填和回看”：打开房间里的方向工作台，访客可临时修改或补入各板块内容，本月行动也可试填；刷新或恢复后回到原始案例，“导出原始案例”不包含试填。Blank 展示“一个人真正开始时什么都还没有”。两者不是同一个人的前后对照；Example 是独立编写的虚构情境，不是私人资料的脱敏版，里面的三件预置当月行动及记录也不是已验证的真实结果。

**已做的源文件检查（PASS，非浏览器验收）：** `examples/teaching-life-grid-monthly.json` 通过当前月度模型的结构校验，含 8 个房间、64 个方向、3 件当月行动；中心、房间、方向的 `source_quote` 均为空。结构与空引用不自动证明全部内容安全或实际交互可用，录制前仍需逐屏核对。

## 高优先级录制阻断项

1. **High · 案例真实性边界。** 画面或口播只要出现“真实案例”“脱敏用户”“真实效果”“已经长期监督”等说法，就会把教学演示伪装成结果证据。统一使用“独立编写的虚构教学情境”“运行方式示意”。
   工作台里的试填与预置案例记录必须区分；“前进证据”可写判断标准，不可把试填文字说成已发生的真实记录。
2. **High · 导入后数据归属。** Blank 在首次打开时为空，但导入后会暂存在当前浏览器。不能称它始终只读，也不能说页面会自动同步私人文件；Personal 私有文件由本地 coding agent 在确认后更新。
   页面“复制给 Coding Agent”的指令已明确区分：有本地文件权限时走 Personal；无文件权限、经确认得到完整 JSON 时，才走 Blank 手工导入。录制时仍需实测复制出的全文与导入后的提示，不能说复制后 Blank 会自动长出内容。
3. **High · 试填不保存。** Example 的方向和行动试填只留在当前页面内存；刷新或恢复即清除，“导出原始案例”也不带走试填。录制不要填写个人敏感信息，也不要称导出为试填备份。
4. **Medium · 恢复路径。** 方向工作台、房间长卷和九宫格连续切换后，应实际确认焦点、滚动位置和房门没有意外跳走；定向编辑 PASS 不等于整段录制 PASS。
5. **Medium · 入口与视口。** `file://` 直开为 BLOCK；从 `./start` 的本机服务地址录制。移动视口覆盖未生效，移动端 NOT_RUN，不能据桌面 PASS 宣称移动端已验收。
6. **Medium · 结果结构。** 打开方向后先让观众看见“想靠近的状态”和四步循环，再展示细节。不要先用 64 格或动画压过核心价值：用户只需选少数当月行动，并留下有来源的记录。

## 录制完成的判定

- 两条入口各留一段无剪辑走通录屏；记下 URL、日期、浏览器、视口和使用的案例文件版本。
- Example：完成九宫格 → 长廊 → 房间 → 方向工作台 → 修改已有板块、补入空白板块 → 可选试填本月行动 → 退出/重开 → 恢复或刷新，并全程可辨“虚构”“试填不保存”。导出按钮应显示“导出原始案例”，手工核对导出的仍是未改动的虚构样本。
- Blank：首次空白 → 复制给 Coding Agent 的本地 Personal 入口 → 可选的**虚构测试 JSON** 手工导入 → 当前浏览器回看 → 导出；不把 Personal 的自动同步错误归因于 Blank，也不在视频里输入私人内容。
- 如果某一步未走通，就在发布材料中保留 `REVIEW` 或 `NOT_RUN`，不要靠剪辑制造已经闭环的印象。
- 移动端在真实移动视口重新走工作台表单前保持 `NOT_RUN`；不要把这次未生效的视口覆盖当成移动端 PASS。`file://` 直开为 `BLOCK`，不作为录制入口。
